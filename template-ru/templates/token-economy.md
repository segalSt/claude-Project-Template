# Экономия токенов (строго)

Переиспользуемые правила для низкого расхода контекста/токенов. Файл правил
сессии и working-conventions ссылаются сюда — не дублировать текст, менять здесь.

## Вывод
- **Английский по умолчанию** (чат, файлы документов, комментарии в коде), если
  пользователь не указал иное — самый плотный/дешёвый язык.
- Пропускать бессмысленные преамбулы/постскриптумы: без "сейчас сделаю…",
  "дай проверю…", "если честно…", "хорошо подмечено", без пересказа только что
  прочитанного, без поэтапных отчётов.
- Итог — не более **одного** предложения с кратким пояснением.
- Прямые ответы/код; не перепечатывать целиком неизменённые файлы; не
  перечитывать только что отредактированный файл.
- Простой язык, без жаргона; кратко, не криптично.

## Контекст и файлы
- Держать часто читаемые/обновляемые контекстные файлы (правила сессии, план,
  история, точка входа) короткими — мягкий потолок ~150-200 строк; детали живут
  в файлах шагов/коде.
- Один источник на факт — ссылаться, не дублировать.
- Предпочитать Markdown для документов; форматированные артефакты (Word/PDF)
  делать только по необходимости.

## Модель, делегирование и длина сессии
- **Подбирать модель/effort под задачу**: самая лёгкая из подходящих; переходить
  на более крупную модель / высокий effort только для сложной работы (нативный
  interop, крупные архитектурные развилки). Подтвердить подходящую модель в начале задачи.
- Делегировать тяжёлые чтения/аудиты (проверки дрейфа, характеризация, обзор
  больших файлов) сабагентам в изолированном контексте — держать основное окно
  чистым, забирать только выводы.
- При **~100k токенов** (или когда контекст явно вырос — точный счётчик может
  быть не виден), **предупредить пользователя и предложить `-park` + свежую сессию**.
