# Implementation plan

Переиспользуемый шаблон. Пошаговый план оставшейся работы - каждый шаг
по возможности = один логический коммит.

**Модель (см. `README.md`):** это план ТЕКУЩЕГО проекта/версии — его фазы-шаги
(спека → план → реализация → проверка → завершение), каждый шаг = 1+ заданий.
Это НЕ реестр разных задач и НЕ история: завершённое и прошлые версии уходят в
`devHistory.md`, не сюда. `-plan` показывает шаги текущей версии.

**Правило актуальности:** этот файл обязан всегда отражать текущее
состояние проекта. Любое изменение проекта, влияющее на статус шага или
описание дизайна внутри шага, отражается здесь же, в том же заходе.
Расхождения, найденные при сверке плана со спекой/кодом — фиксируются в
`errors.md` (не чинятся молча), статус `Open`/`Fixed`. Любая последующая
правка обязана также проверить, что уже `Fixed`-записи не вернулись.

**Правило ссылки на шаг:** при обсуждении в чате любого действия,
которое относится не к текущему шагу — называть номер шага, к которому
оно относится. Если действие не покрыто ни одним существующим шагом —
сказать об этом явно.

**Правило каталога тестов** (если в проекте есть автотесты):
`tests-catalog.csv` (номер, файл, тест, что проверяет) обновляется в том
же заходе, что и любое изменение тестов.

**Когда разбивать план на файлы (масштабируемая раскладка).** Пока план
небольшой — все шаги живут прямо в этом файле. Когда `plan.md` перестаёт
быть дешёвым для чтения — разнести тело каждого шага в отдельный файл:
активные — `plan/step-<N>.md`, закоммиченные — `plan/archive/step-<N>.md`.
В `plan.md` остаётся только: мета-правила + `## Индекс шагов` (№, название,
статус УРОВНЯ шага, ссылка на файл) + сквозные разделы (TBD/Ошибки/Не
входит/Git). Тело шага = `### Задачи` (таблица задач — единственный
источник статусов задач, правило 11) + дизайн + `### Ручное QA`.

**Явный порог (ориентир, не догма) — разбивать, когда выполнено любое из:**
- `plan.md` превышает **~400 строк**; или
- тело любого ОДНОГО шага превышает **~150 строк**; или
- шагов с содержательными телами больше **~10**.

Триггер-признак: каждое чтение плана тянет за собой сотни строк уже
закрытых/неактуальных шагов. Разбиение — механическая операция (лучше
скриптом/shell, чем ручной перепечаткой); закрытые шаги безопасно живут в
git-истории, детальную многосотстрочную историю закрытого шага можно не
переносить дословно, оставив в его файле таблицу `### Задачи` + указатель
на git.

## TBD (обсудить перед применением)

Темы, отмеченные командой `-tbd <текст>` (`commands.md`) - зафиксированы
сразу, чтобы не потерять, реализация/изменение плана по ним не начинается
без явного обсуждения и решения. Статус: `Open` (ждёт обсуждения) →
`Discussing` (обсуждается) → `Accepted` (принято, перенесено отдельным
шагом/правкой - указать номер шага) или `Rejected` (отклонено - остаётся в
таблице для истории, не удаляется).
