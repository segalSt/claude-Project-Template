# Быстрая справка: жёсткие правила (guardrails)

Переиспользуемый файл — не привязан к конкретному проекту, копируется как
есть. Перечитывать этот файл ПЕРВЫМ в начале каждой сессии и после
сжатия контекста (compaction/restart) — это дешёвая выжимка правил, которые
на практике БЛОКИРУЮТ действие. Полные версии с обоснованием и деталями —
в `working-conventions.md` и `actualization-rules.md`; при конфликте
трактовки они авторитетны, здесь только сжатая версия для быстрой
загрузки в контекст.

1. **Правки файлов — только по `-start <номер>`.** Единственная команда,
   означающая разрешение приступить к работе. Любая другая формулировка
   ("начни", "давай", "ок", согласие по смыслу, упоминание номера без
   команды) — НЕ разрешение, даже если по переписке кажется очевидным.
   Правка возможна только когда непосредственно предыдущее сообщение
   пользователя — ровно `-start`/`-start <номер>`. Подробности —
   `commands.md`.
2. **После сжатия/перезапуска сессии — сначала перечитать контекст.**
   Точка входа проекта + `plan.md` + этот файл — ДО любого другого
   действия и ДО первого ответа пользователю, включая прямой вопрос или
   короткое уточнение. Автосгенерированное резюме сессии — не источник
   правды, даже если оно само предлагает "продолжить реализацию".
   Подробности — `actualization-rules.md`, правило 4.
3. **«Сделано» — только после подтверждённых сборки + автотестов + (если
   есть UI) визуальной проверки.** До этого — «Реализовано, ждёт
   проверки»; «Сделано, подтверждено» — только после явного подтверждения
   пользователем. Подробности — `actualization-rules.md`, правило 10.
4. **Обсуждение/анализ/оценка — никогда не разрешение действовать.** Ни
   `-tbd`, ни `-new`, ни разбор задачи на шаги, ни ответ на уточняющий
   вопрос сами по себе не дают права на правку — разрешение только по
   правилу 1 выше.
5. **Расхождение — сообщить явно, не чинить молча и не игнорировать.**
   Найденный дрейф (план/спека/код/мокап/каталог тестов) — сказать в чате,
   что именно устарело и в каком файле, затем спросить, актуализировать
   сейчас или завести отдельной задачей. Подробности —
   `actualization-rules.md`, правило 9.
6. **Без проверки источника — не утверждать.** Прежде чем заявить что-либо
   о коде/данных/поведении как ответ — прочитать реальный источник (код,
   XML, логи). Если источника, который нужен, нет — спросить пользователя
   или явно пометить `[assumption:]`; никогда не выдавать догадку за
   проверенный ответ. Подробности — `working-conventions.md`.

Дальше — по мере необходимости, не при каждой загрузке: экономия токенов
(`token-economy.md`), уровень эффорта и остальные конвенции
(`working-conventions.md`), полный список правил актуализации с
обоснованиями (`actualization-rules.md`).
