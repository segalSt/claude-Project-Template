# Назначение и модель работы (шаблон контекста)

Переиспользуемый набор файлов контекста для работы с ИИ-ассистентом над
программным проектом. Держит правила, план и историю в порядке, чтобы
ассистент соблюдал дисциплину на длинных сессиях и не «плыл» по мере роста
контекста. Это **базовое понимание** — все остальные файлы шаблона следуют
ему.

## Принцип (как устроена работа)

Шаблон описывает работу над **ОДНИМ проектом/версией за раз**, разложенную на
базовые фазы-шаги:

1. **Спека (интервью)** — определить, ЧТО делаем (`docs/SPEC.md`).
2. **План** — разложить спеку на шаги реализации (`docs/plan.md`).
3. **Пошаговая реализация** — по одному шагу.
4. **Проверка** — тесты + ручное QA.
5. **Завершение** — коммит/выпуск версии; переход к следующей версии.

Каждый шаг/фаза = **1+ заданий** (tasks).

### Единица работы (масштаб)

«Один проект/версия» — это масштаб, и он может быть двух видов:
- **целый проект** (пример — tagsExpert: приложение целиком);
- **один рабочий элемент** — user story / bug из DevOps-доски внутри большого
  проекта (пример — Kolnatun / задача 28476).

В обоих случаях контекст ведёт **ОДНО целое** — один связный элемент работы,
разложенный на фазы. **Параллельных независимых тасков в одном контексте не
бывает** (нельзя вести 28476 и 16446 разом): другой элемент = другой контекст;
завершённые/прошлые элементы — в историю.

Отсюда — ключевые следствия (их обязаны соблюдать `plan.md`, команды,
`migration.md`, `new-project-setup.md`):

- **`plan.md` — это план ТЕКУЩЕГО проекта/версии** (его шаги-фазы), а НЕ реестр
  разных задач и НЕ история.
- **`-plan` показывает шаги текущей версии** (что делать по плану), а не список
  прошлых/несвязанных задач.
- **Завершённая работа и прошлые версии → в историю** (`docs/devHistory.md`),
  НЕ в план. Отдельные независимые задачи прошлого — это история, а не строки
  текущего плана.
- Когда версия завершена — план очищается/переходит к следующей версии, а
  сделанное уходит в историю.

## Файлы

- точка входа `<Проект>Prompt.md`, `commands.md`, `working-conventions.md`,
  `actualization-rules.md`;
- `docs/SPEC.md`, `docs/plan.md` (+ `docs/plan/` при разрастании — см. порог в
  `templates/plan-template.md`), `docs/errors.md`, `docs/devHistory.md`.

## Точки входа

- **Новый проект с нуля** → `new-project-setup.md`.
- **Мигрировать существующий проект** на эту структуру → `migration.md`
  (команда `-миграция`/`-migrate`).
- Синхронизация RU/EN копий шаблона → `SYNC.md`.
